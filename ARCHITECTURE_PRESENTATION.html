AI Travel Harness

A zero-trust framework that an untrusted AI agent lives inside. Five agents plan a trip — Flight · Hotel · Car · Experience · Food — but the agents are the product; the harness is what is being defended and judged.
An agent proposes an ID and nothing more. The harness independently re-grades every claim against data the agent does not control, builds every link itself, persists all state, and raises a structured alarm on every violation.

1The real-world problem

Agentic systems are useful because they take action — they book, link, and spend real money. That is also their threat surface. You cannot fix this by asking the model to "be careful." The agent's word can never be the final word.

2The idea — wrap the agent in a harness

3System architecture — five layers

Nothing crosses a layer boundary unvalidated. Layer 4 (the harness) sits in the gap between an agent's proposal and a booking.

LAYER 1 · Front End
CLI (main.py) or Streamlit web app — trip request in → HTML itinerary + whitelisted links out
LAYER 2 · Orchestrator
LangGraph StateGraph — runs nodes, wraps each with the harness, routes on the checkpoint verdict, replays from last good state, escalates to a human via interrupt()
LAYER 4 · 🛡 Harness
The four pillars, all outside the agents: ① Guardrails   ② Checkpoints   ③ Material Handling   ④ Alarms  —  node_wrapper.py composes all four around one untrusted agent
LAYER 3 · Agents
Untrusted, swappable workers · one contract: run(scoped_input, feedback) → Proposal   ✈ Flight🏨 Hotel🚗 Car📍 Experience🍽 Food

The only layer that persists: SQLite checkpoints ./runs/<id>/Seed inventory (ground truth)UserStore session memoryDocker — no ambient trust

4The four pillars — what the agent gets for free

① Guardrails

  • Input sandbox — raw request → strict TripProfile (Pydantic); only typed, range-checked fields flow on.
  • IDs-not-URLs — every proposal subclasses NoUrlModel; any URL is rejected.
  • Shadow Auditor — a 2nd deterministic grader re-checks each claim against ground-truth inventory (rating ≥ floor, price ≤ budget, claim == reality, dietary gate).
  • Economic + Budget Guardrail — token/$ ceilings; caps/floors keep the budget split realistic.

② Checkpoints

  • Explicit pass/fail gate after every node (schema valid + auditor passed), with the tripped criterion broken out for telemetry.
  • State persists only on PASS → a failed node replays from the last good checkpoint; upstream work is never recomputed.
  • 3 strikes → human escalation, never a fabricated booking.

③ Material Handling

  • A declared SCOPE table is the authority policy — clean interfaces in and out.
  • route() projects the profile down to one agent's typed slice; assert_scoped() is a hard invariant.
  • Least authority by construction — money agents never receive diet/cuisine/activities; the Flight agent can't leak data it never sees.

④ Alarms

  • Every tripped rule emits one structured JSON record: type · severity · context · recommended_action.
  • Severity = CRITICAL / WARNING / INFO; alarms only observe — control flow is decided by the checkpoint logic.
  • Splunk-ready — set SPLUNK_HEC_URL/TOKEN for a live HTTP Event Collector sink (stdlib, no SDK).

5How the agents work & communicate — the per-agent gauntlet

Agents never talk to each other and never touch shared state. All communication flows through the harness. Every agent runs this identical gauntlet, so an agent gains no authority by being "smarter."

1
Economic Governor — over the token/$ budget? → CRITICAL alarm + halt before the agent even runs.
2
Material Handler · route() — scope the validated profile to this agent's least-authority slice (allocated budget + party size only).
3
🤖 Untrusted agent · run(scoped, feedback) — proposes IDs + claimed_* numbers. No URLs · no free text · no state writes. Honors feedback from a prior failure.
4
Output Guardrail + Shadow Auditor — re-validate schema & reject URLs; look the ID up in ground truth; compare claim vs reality (hallucinated ID, inflated rating, threshold/dietary violation).
5
Checkpoint · evaluate() — combine the deterministic signals into one explicit verdict.
✓
PASS → Link Builder mints a whitelisted link from the validated ID → persist state → INFO alarm → advance to next agent.  |  FAIL → feedback + WARNING → replay same node.  |  3rd FAIL → CRITICAL → human interrupt().
The two communication rules that make it zero-trust:
❌ raw user text never reaches an agent  ·  ❌ agents never emit URLs or write state  ·  ❌ money agents never see diet / cuisine / activities. Inbound = typed scoped slice; outbound = opaque IDs + claims, independently re-graded.

6How the final outcome is produced

StageWhat the harness does
allocateSplit one total_budget by priority; Budget Guardrail caps/floors it; if preferences > budget → pause pre-booking (accept overage / apply cuts).
agentsRun only the included services (drive own car → no flight/car: $0, never execute), each through the §5 gauntlet.
reconcileSum the actual validated costs vs budget; a residual overrun is a WARNING, never a hidden charge.
